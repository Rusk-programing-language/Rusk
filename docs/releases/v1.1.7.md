# Rusk v1.1.7 — a more useful experimental Windows target

Rusk bakes ahead of time: it emits native machine code directly, with no
assembler, linker, libc, or runtime. This patch keeps the Linux and toast
behaviour of v1.1.6 and makes the experimental Windows x86-64 output do more of
what a small console program actually needs.

## New in v1.1.7

- **Command-line arguments.** The PE startup thunk now splits the real Windows
  command line into `argv`, so `all arguments`, `argument N`, and `number of
  arguments` work. Up to 1024 words are kept. Quoting follows the everyday
  Windows rules: whitespace separates words unless it is inside double quotes,
  a quote toggles quoting, empty quoted words are preserved, and backslash
  escapes are not interpreted.
- **Environment variables.** `environment NAME` reads the process environment
  through `GetEnvironmentStringsA`. Missing names still give empty text.
- **Regular file I/O.** `read file` and `write ... to file` now work through
  `CreateFileA`, `ReadFile`, `WriteFile`, and `CloseHandle` instead of stopping
  at the unsupported-feature message. The existing path buffer limit still
  applies.
- **Raw terminal mode.** `turn on raw terminal` and `turn off raw terminal`
  use `GetConsoleMode` and `SetConsoleMode` to change console input, including
  virtual-terminal input, and restore the saved mode. A redirected pipe is left
  alone. `read key` returns the byte it receives.
- **Better console output.** The startup thunk enables virtual-terminal
  processing for standard output when it is a console, so ANSI colour and cursor
  escapes keep working in normal Windows terminals.
- **Fixed a Windows call-frame bug.** Restoring the stack after a `kernel32.dll`
  call emitted `mov r12, rsp` instead of `mov rsp, r12`. That corrupted the
  caller's stack and made later file reads and output crash; the encoding is
  corrected, and the Windows scratch data addresses are emitted as full 64-bit
  addresses because the image sits above 4 GiB.

| Release | What it added |
|---|---|
| v1.1.3 | Systems core: directories, `run command`, `all arguments`, a growable `mmap` heap, 128 parameters |
| v1.1.4 | IPv4 TCP sockets and raw terminal input |
| v1.1.5 | Large-heap growth and directory-listing fixes |
| v1.1.6 | Portable `.tst` toast files, the first experimental Windows `.exe` target, bundled `installwork`, `wheat`, and `Ruskfile` projects |

The language, the Linux AArch64/x86-64 output, and toast files are unchanged in
this patch. The standard modules, `rusklib/`, `wheat`, the installer framework,
the Ruskfile runner, the REPL/TUI, and `selfhost/interpreter.rk` remain ordinary
Rusk source in the tree.

## Install or upgrade

```console
curl --proto '=https' --tlsv1.2 -sSf \
  https://raw.githubusercontent.com/Rusk-programing-language/Rusk/main/toastset | sh
```

Prebuilt archives are attached for AArch64 and x86-64, glibc and musl, plus a
Windows x86-64 `rusk.exe`. Existing installs upgrade in place when `toastset`
is run again. The Windows archive still contains the compiler, so a Windows
host builds `.exe` output and cannot run the Linux ELF it also bakes.

## Honest limits

- Windows x86-64 output is still experimental and console-only. `file exists`,
  directory calls, process launch, and sockets print
  `burnt: this Windows build does not support that feature yet` and exit 1.
- The command line is capped at 1024 words. The quoting rules are simplified:
  there is no backslash-escape handling and no `CommandLineToArgvW` parity.
- The PE image is fixed-base with no base relocations, so Windows must load it
  at its preferred address.
- Raw mode needs a real console. Redirected input is left unchanged.
- Generated `.exe` behaviour is checked in development with an x86-64 emulator
  and `kernel32` stubs, not by running Windows in CI. CI builds and tests the
  compiler itself on Windows, but does not start the baked `.exe`.
- Linux remains the supported output platform. The Windows target is an
  experimental way to run small console programs, not full parity.
