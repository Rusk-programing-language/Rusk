# Rusk v1.2.2 — diagnostics, native Windows setup, and faster bakes

Rusk bakes ahead of time: it emits native machine code directly, with no
assembler, linker, libc, or runtime. This patch keeps the v1.2.1 GUI work
intact and fixes the post-release reports about error codes, REPL editing,
Windows installation, and compiler speed.

## New in v1.2.2

- **Fixed error codes.** `E01` is always a syntax error. A category no longer
  gets a new number during a session: `E02` type, `E03` ownership, `E04`
  runtime, `E05` import, and `E06` usage. The exact question string
  `Do you want to edit this code using the REPL y/n` is unchanged.
- **Full-code REPL editing.** Before that question, the REPL prints every line
  that was submitted, not just the offending block. Answering `y` reopens all
  of it with the cursor ready. The plain REPL, full-screen TUI, and
  `rusk build`/`run`/`check` paths now behave the same way.
- **Native Windows installer.** `toastset.ps1` installs from a plain PowerShell
  window using the original working flow: TLS 1.2, the latest GitHub release,
  `curl.exe`, `tar.exe`, `%LOCALAPPDATA%\Rusk`, the user `PATH`, and a prompt
  before creating `Rusk.lnk` in the Startup folder. `toastset` delegates to it
  automatically on Windows; Git Bash is no longer required.
- **Full source in the archives.** Every release archive now carries both
  `toastset` and `toastset.ps1`, plus the whole `rusklib/` tree. The bundled
  wheat terminal UI library is therefore in `rusklib/wheat/` inside the
  download as well as on GitHub `main`, alongside its `README.md` and all
  modules.
- **Compiler optimizations.** `src/optimize.rs` folds literal arithmetic and
  comparisons, resolves constant branches and short-circuits, drops statements
  after unconditional exits, and preserves function labels from discarded code.
  The x86-64 emitter uses shorter 32-bit immediate moves, drops self-moves, and
  spills the least recently used pool register.
- **Benchmarks and regression tests.** `cargo bench` reports code-generation
  time, text and image size, and baked-program run time with the pass off and
  on. Tests cover the fixed codes, whole-source editing, the installer docs and
  script, and the optimization gains.

## Where this fits

| Release | What it added |
|---|---|
| v1.2.0 | `rdb`, live REPL syntax colouring, word-wise editing, numbered diagnostics, and the bundled Windows SVG logo |
| v1.2.1 | Native `simple` GUI primaries on Windows x86-64 and the `fastlib/simple` library |
| v1.2.2 | Fixed diagnostic categories, full-code REPL editing, native Windows installation, and compiler optimizations |

The language rules, the Linux AArch64/x86-64 output, toast files, `Ruskfile`
projects, `rdb`, the TUI, and the v1.2.1 GUI surface are unchanged.

## Honest limits

- The REPL question is still skipped when stdin is a pipe, so scripts do not
  block.
- Constant folding does not turn a division by zero or an arithmetic overflow
  into a compile error; those still reach the runtime.
- The x86-64 gains come from smaller immediate encodings, fewer emitted moves,
  and better register reuse; there is no global allocator across branches or
  calls yet. `cargo bench` prints the baked-program run time too, but a tight
  generated loop is sensitive to instruction alignment, so treat that line as
  informational; compile time and code size are the stable measurements.
- Native GUI and the Windows installer need a real Windows machine for final
  smoke testing. Linux CI checks the installer script and PE bytes, not a live
  Windows desktop session.
- Records and structs remain a later feature.
