# Rusk v1.2.3 — full module library and npmwork

Rusk bakes ahead of time: it emits native machine code directly, with no
assembler, linker, libc, or runtime. This patch keeps the v1.2.2 compiler,
diagnostics, GUI, and installer work intact, and completes the bundled library
layout from `guide/new`.

## New in v1.2.3

- **One folder, one module, one prefix.** Shared generic modules live in
  `ruskmods/<name>/<name>.rk`, system and IO modules live in
  `rusklib/<name>/<name>.rk`, and installer frameworks keep their own folder
  with internal modules. Root-level `<name>.rk` files are compatibility shims
  that forward to the folder module.
- **New generic modules.** `bytes`, `text`, `maps`, `result`, `semver`,
  `manifest`, `lock`, `archive`, `fs`, `sha`, and `gzip` join `math`, `date`,
  `time`, `random`, `statistics`, `json`, `toml`, `sys`, `os`, `path`, and
  `shutils`. The shared `text_*` helpers moved to `ruskmods/text/text.rk`, and
  `rusklib/wheat/text.rk` imports them explicitly.
- **New system and IO modules.** `rusklib/http`, `cache`, `fs_fast`, `platform`,
  `term`, and `bench` sit beside the canonical `rusklib/files/files.rk`.
  `rusklib/files.rk` remains a forwarding shim, so both path styles work.
- **Bundled imports work from anywhere.** A path with a slash now also finds a
  same-named file inside a folder, so `import "json/json"` and
  `import "rusklib/http"` work as documented. The compiler also searches beside
  its own executable last, so an installed `rusk` finds the libraries that
  shipped with it even when the program lives in another directory.
- **The `npmwork` framework.** `import "npmwork"` brings in a JS/TS package
  framework with `package.json` reading, `semver` requirements, a resolver,
  `curl`-backed registry downloads, `node_modules` installation, a text lock
  file, global prefixes, project commands, and a CLI. `installwork` also gains
  shared `semver` and `manifest` wrappers.
- **One-import bundle.** `import "rusklib/rusklib"` now pulls in every generic
  module, both installer frameworks, the system/IO modules, `files`, and wheat.
  A program can still import any single module directly.
- **Complete release archives.** Every archive now includes `ruskmods/`,
  `rusklib/`, and `fastlib/`, in addition to `toastset`, `toastset.ps1`, the
  README, licence, and logo. The v1.2.2 archives predate these additions.
- **Documentation and regressions.** The README, guide, `ruskmods/` and
  `rusklib/` READMEs, and `docs/SPEC.md` describe the new layout. Tests check
  every module file, the exact imports from `guide/new` from outside the
  checkout, and a runtime program using the new libraries together.

The exact string `Do you want to edit this code using the REPL y/n` and the
Windows startup prompt `Add Rusk to the Windows Startup folder so the prompt
opens at login? [y/N]` are unchanged.

## Honest limits

- Rusk still has no native SHA, gzip, HTTP, TLS, DNS, clock, map, or result
  primitive. `sha` and `gzip` use the matching POSIX commands, `http` uses
  `curl` for DNS and TLS, and `bench` uses `date +%s%N`. These limits are
  documented beside each module.
- Raw Rusk sockets remain IPv4-only with no DNS, TLS, or timeouts, so `http`
  deliberately uses `curl` rather than pretending raw sockets are enough.
- `npmwork` builds registry URLs and downloads tarballs. It does not run npm
  lifecycle scripts, parse a full npm metadata index, or replace npm.
- Native GUI and the Windows installer need a real Windows machine for final
  smoke testing. Linux CI checks the installer script and PE bytes, not a live
  Windows desktop session.
- Records and structs remain a later feature.
