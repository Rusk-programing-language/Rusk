# Rusk v1.2.5 — Windows installer and `simple` GUI fixes

Rusk bakes ahead of time: it emits native machine code directly, with no
assembler, linker, libc, or runtime. This patch keeps the v1.2.4 compiler,
diagnostics, libraries, debugger, and module work intact, and fixes two problems
reported after that release: the native Windows installer script failing to
parse in Windows PowerShell, and `simple` programs not delivering GUI events to
the Rusk event loop.

## New in v1.2.5

- **The Windows installer parses in Windows PowerShell 5.1.** `toastset.ps1` is
  now ASCII-only. The previous script was UTF-8 without a BOM but contained em
  dashes; Windows PowerShell 5.1 read the bytes as ANSI, turned one into a smart
  quote, and reported `The string is missing the terminator: "."` before
  `iex` could run the script. The raw `main` script and every release archive
  now contain the fixed file.
- **Clearer installer commands.** The README and guide now say to run
  `powershell -ExecutionPolicy Bypass -File .\toastset.ps1` from the folder that
  contains the script, because `-File toastset.ps1` only works when that file is
  in the current directory. The one-line download uses
  `irm ... -UseBasicParsing | iex`, which avoids the legacy IE parsing path.
  The exact Windows startup prompt is unchanged.
- **`next simple event` returns the recorded event.** The generated control
  flow used to fall through to the empty-string branch after selecting `click`,
  `change`, or `close`, so documented `simple_event_wait` loops could spin
  forever. Event branches now jump over the empty-string path; only a genuinely
  empty queue returns `""`.
- **Closing a window records `close`.** The compiler-emitted `WndProc` now
  stores a `close` event with control `0` and value `0`, increments the event
  count, and then posts `WM_QUIT`. A Rusk loop sees the same `close` event
  whether the user clicks the X button or the program calls
  `close simple window`.
- **GUI docs match the runtime.** The README, guide, `fastlib/` docs, and
  `docs/SPEC.md` now say that `show simple window` shows
  and updates the window but does not start a message loop. Programs must keep
  pumping events after opening it, and `--target windows` is required because
  the default target and `rusk check`/REPL use typed no-ops. The `simple` README
  has a troubleshooting checklist covering target, event loop, bundled
  libraries, the single-window limit, and the console subsystem.
- **Regressions.** Tests check that `toastset.ps1` is ASCII-only, that the docs
  use the corrected commands, that the event path jumps over the empty string,
  and that `WndProc` emits click, change, and close kind records.

The exact string `Do you want to edit this code using the REPL y/n` and the
Windows startup prompt `Add Rusk to the Windows Startup folder so the prompt
opens at login? [y/N]` are unchanged.

projects, `rdb`, the TUI, and the module set are unchanged.

## Honest limits

- Native GUI and the Windows installer still need a real Windows machine for
  final smoke testing. Linux CI checks the installer script and PE bytes, not a
  live Windows desktop session.
- The emitted PE still uses the console subsystem and only one `simple` window
  is supported at a time; a console window may appear next to the GUI window.
  This remains an experimental target.
- There is still no native SQLite binding. The v1.2.4 database library shells
  out to the system `sqlite3` command with CSV output redirected to files.
- Records and structs remain out of scope.
