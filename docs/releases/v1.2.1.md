# Rusk v1.2.1 — a native GUI library written in Rusk

Rusk bakes ahead of time: it emits native machine code directly, with no
assembler, linker, libc, or runtime. This release keeps the compiler, the Linux
targets, toast files, and the interactive tools unchanged and adds a small
native GUI surface plus the library built on top of it.

## New in v1.2.1

- **GUI primaries.** `make simple window`, `add simple button/label/field`,
  `show simple window`, `close simple window`, `set simple text of`,
  `simple text of`, `show simple message`, `simple confirm with`,
  `pump simple events`, `next simple event`, and `simple event control` are
  now part of the language. On Windows x86-64 they create real Win32 controls;
  on Linux and AArch64 they are typed no-ops, so the same source checks and
  bakes everywhere.
- **`fastlib/simple`.** Thirty-one `.rk` files wrap the primaries and add
  geometry, layout, events, dialogs, colours, themes, menus, toolbars, status
  bars, progress, list boxes, a character canvas, key names, drag-and-drop
  payloads, and a `ttk` layer. `import "simple/simple"` pulls in the bundle;
  `import "simple/event"` pulls in one module. See
  [`fastlib/simple/README.md`](../fastlib/simple/README.md).
- **Runtime-linked user32.** The Windows GUI calls are loaded with
  `LoadLibraryA` and resolved with `GetProcAddress`, so the PE import table
  still names only `kernel32.dll`. The `WndProc` is emitted by the compiler and
  records events into data slots; the Rusk program reads them in its own polling
  loop instead of crossing a language callback boundary. The PE keeps the CUI
  subsystem.
- **Library resolution.** Bare imports now also search `fastlib/` beside the
  program and in each parent directory, alongside `ruskmods/` and `rusklib/`.
- **No new dependencies.** The GUI layer, the library, and the event loop are
  hand-written Rusk and hand-emitted machine code using the existing compiler
  pipeline. The Windows `toastset` Startup shortcut behaviour from v1.2.0 is
  unchanged.

release.

## Honest limits

- Native GUI support is Windows x86-64 only. Linux, AArch64, and the REPL accept
  the syntax but show no window. There is no macOS or 32-bit GUI output.
- The native control set is buttons, labels, fields, message boxes, and confirm
  boxes. `frame`, `menu`, `toolbar`, `canvas`, `listbox`, `progress`, and `dnd`
  are Rusk-level models rendered into labels; they are not native widgets.
  There is no native key event, tree view, real drag-and-drop, or HiDPI layout.
- Events are polled (`pump simple events` / `next simple event`) and carry only
  `""`, `click`, `change`, or `close`, with the originating control available
  from `simple event control`.
- The emitted PE uses the CUI subsystem, so a GUI program still starts with a
  console attached. Windows GUI behaviour was verified by baking and inspecting
  a PE, not by a Windows CI runner; manual smoke testing on Windows is still
  valuable.
- Text remains immutable and the heap does not reclaim joined text, as in
  v1.2.0. Records and structs are still a later feature.
