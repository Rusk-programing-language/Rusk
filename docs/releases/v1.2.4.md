# Rusk v1.2.4 — database library and installed-library fix

Rusk bakes ahead of time: it emits native machine code directly, with no
assembler, linker, libc, or runtime. This patch keeps the v1.2.3 compiler,
diagnostics, GUI, debugger, and module work intact, adds a SQLite-like
`rusklib/database` library, and fixes library lookup for installed compilers.

## New in v1.2.4

- **`rusklib/database`.** `import "rusklib/database"` brings in a database
  library modelled on Python's `sqlite3` files. `dbapi2.rk` provides
  connect/cursor/execute/fetch/close, `completer.rk` provides keyword and dot
  completion, `dump.rk` produces SQL dump statements and restores them,
  `cli.rk` provides a SQLite-like REPL and one-shot driver, and `database.rk`
  is the one-import facade. The public prefix is `db_`.
- **Python-shaped API in plain Rusk.** Connections are `["file", path]` or
  `["memory", temporary path]`, cursors are
  `[database path, rows file, error file]`, and rows are lists of text.
  Operations give back `result` values. `:memory:` is emulated with a temporary
  file so it survives across statements; `db_close` removes it.
- **Installed compilers find their libraries.** The POSIX `toastset` now copies
  `ruskmods/`, `rusklib/`, and `fastlib/` beside the `rusk` binary and removes
  them on uninstall. This fixes the reported failure where an installed
  compiler could not resolve `import "simple/simple"` from another directory.
  The native Windows installer already extracted the full archive, and now
  removes those folders on uninstall too.
- **Missing imports are import errors.** The `I can't find the file ...` message
  from the resolver is now classified as `E05` with the import hint instead of
  being shown as `E04` with a runtime hint. The REPL edit question wording is
  unchanged.
- **Documentation and regressions.** The README, guide, `rusklib/README.md`,
  and `docs/SPEC.md` describe the database library and its limits. Tests check
  every new module file, the exact imports from the module guide from outside
  the checkout, the installer's library handling, and database helpers with and
  without a `sqlite3` command.

The exact string `Do you want to edit this code using the REPL y/n` and the
Windows startup prompt `Add Rusk to the Windows Startup folder so the prompt
opens at login? [y/N]` are unchanged.

## Honest limits

- There is still no native SQLite binding. The database library shells out to
  the system `sqlite3` command with CSV output redirected to files, so it needs
  that command on `PATH`. Rows are text only, each statement is a separate
  process, transactions do not survive between statements, and `?` parameters
  are quoted text substitutions rather than full DB-API binding.
- The database CLI uses `read line`, not `readline`: it has no history,
  raw-mode editing, or callbacks. An empty line or end of input leaves the REPL.
- Records and structs remain out of scope.
- Native GUI and the Windows installer need a real Windows machine for final
  smoke testing. Linux CI checks the installer script and PE bytes, not a live
  Windows desktop session.
