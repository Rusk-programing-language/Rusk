# Rusk v1.2.0 — debugging, coloured editing, and numbered errors

Rusk bakes ahead of time: it emits native machine code directly, with no
assembler, linker, libc, or runtime. This release keeps the compiler and all
existing targets unchanged and gives the interactive side of the tool a much
better editor: live syntax colouring, word movement, a real debugger, and error
reports that can reopen the offending code.

## New in v1.2.0

- **`rdb`.** Start it with `:rdb [file.rk]` in the REPL or `rusk rdb [file.rk]`
  from a shell. `step` runs one top-level statement, `continue` runs to the next
  breakpoint, `break N` / `delete N` manage line breakpoints, and `breaks`,
  `list`, `where`, `print NAME`, `vars`, `functions`, `load FILE`, and `quit`
  inspect the session. The debugger uses the same lexer, parser, type checker,
  ownership checker, and evaluator as the prompt; it does not fork the language.
- **A coloured line editor.** The normal prompt now works in raw mode on a
  terminal. Keywords, text, numbers, comments, names, and operators are coloured
  while the line is typed. Arrows move by character; Ctrl/Alt+Left and
  Ctrl/Alt+Right move by word (Alt-b/Alt-f work too). Home/End, history,
  Tab, Ctrl-A/E/U/K/W/L, and UTF-8 editing are supported. Pipes still get plain
  cooked input with no prompts.
- **Numbered diagnostics.** Mistakes are printed as `E01`, `E02`, … with a
  category, line number, source line, explanation, and hint. The prompt follows
  the report with `Do you want to edit this code using the REPL y/n`; answering
  `y` puts the offending block back at the prompt with the cursor ready. The CLI
  uses the same report for bake and check errors and skips the question when
  stdin is not a terminal.
- **Windows logo asset.** Linux and Windows release archives now include
  `assets/rusk-logo.svg`, so the README's SVG logo resolves in the installed
  package. `rusk logo` prints that SVG on Windows and the ASCII wordmark
  elsewhere. The release workflow now waits for the Windows job before
  publishing assets.
- **Optional Windows startup shortcut.** `toastset` now asks
  `Add Rusk to the Windows Startup folder so the prompt opens at login? [y/N]`
  and, on `y`, creates `Rusk.lnk` in the personal Startup folder pointing at
  the installed `rusk.exe`. `--no-startup` skips the question, and
  `--uninstall` removes the shortcut.
- **No new dependencies.** Colouring, editing, diagnostics, and debugging are
  hand-written modules using the existing `tui` ANSI and key decoder.

## Honest limits

- `rdb` steps **top-level statements**. A whole function definition is one
  step, and calls inside it are not stepped into. There are no local-variable
  or instruction-level breakpoints yet.
- Diagnostics wrap the pipeline's first error, as before. A single submission
  still fails fast rather than collecting every independent mistake at once.
- The line editor uses plain ANSI sequences. It needs a real terminal with
  colour support; over a pipe everything remains plain text.
- Word movement treats letters, digits, and `_` as one word; punctuation is
  skipped between words. Terminals that do not send modifier information for
  Ctrl/Alt+arrow can use Alt-b and Alt-f instead.
- The Windows SVG asset is documentation and branding. Windows PE executables
  do not carry the SVG as an icon resource; there is no GUI icon in this
  console-only release.
