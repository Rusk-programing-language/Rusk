# Rusk v1.1.6 — toast files and an experimental Windows target

Rusk bakes ahead of time: it emits native machine code directly, with no
assembler, linker, libc, or runtime. This release adds a portable precompiled
container and the first Windows output.

## New in v1.1.6

- **Toast files (`.tst`).** `rusk toast hello.rk` bakes a program once into a
  portable container that holds the finished code, read-only data, zeroed-data
  size, and per-image import names. `rusk run hello.tst`, `rusk build hello.tst`
  and `rusk check hello.tst` understand it without the source. A toast defaults
  to both Linux architectures and can hold one image per target, up to eight.
- **An experimental Windows x86-64 target.** `rusk build hello.rk --target
  windows` writes a PE32+ `.exe` with imports from `kernel32.dll`. Console
  output and input, process exit, the heap, and the command line are mapped;
  unsupported calls fail with a clear message instead of a broken binary.
- **Bundled projects and UI.** The installer framework (`ruskmods/installwork/`),
  the `wheat` terminal UI library (`rusklib/wheat/`), and `Ruskfile` task
  runners are in the v1.1.6 tree. `installwork init NAME` now writes a starter
  project that builds cleanly, and the generated `Ruskfile` no longer emits an
  untyped empty list.
- **Docs.** The README, the guide, and `docs/SPEC.md` document the toast
  layout, the Windows milestone, and its honest limits.

## How Rusk got here

Each release kept the same shape — one static executable, no dependencies —
while the language and the systems surface grew:

| Release | What it added |
|---|---|
| v0.1 | English-like language baking native AArch64 ELF |
| v0.2 | Functions, `give back`, recursion, typed parameters |
| v0.3 | Text joining and comparison, `while`, `for each`, `otherwise if` |
| v0.4 | Text length, indexing, slicing, and the interactive session |
| v0.5 | Constants, lists, and recursive imports |
| v0.6 | Ownership checking, runtime guards, `break`/`continue`, short-circuit logic, growable lists, system I/O, the terminal UI module, and the full-screen session |
| v0.7 | List removal and capacity |
| v0.8 | The x86-64 backend |
| v0.9 | Nested lists and module namespaces |
| v1.0 | Borrowed views, function values, and closures |
| v1.1 | First-class functions, a register-allocating x86-64 encoder, exports, and the self-hosting interpreter |
| v1.1.1 | Statically linked musl builds, Termux-aware `toastset` |
| v1.1.2 | Windows host fixes |
| v1.1.3 | Systems core: directories, `run command`, `all arguments`, a growable `mmap` heap, 128 parameters |
| v1.1.4 | IPv4 TCP sockets and raw terminal input |
| v1.1.5 | Large-heap growth and directory-listing fixes |

Those features are still present in v1.1.6. The standard modules
(`math`, `date`, `time`, `random`, `statistics`, `json`, `toml`, `sys`, `os`,
`path`, `shutils`), `rusklib/`, `wheat`, the installer framework, the Ruskfile
runner, the REPL/TUI, and `selfhost/interpreter.rk` are all ordinary Rusk
source in the tree; nothing is downloaded separately.

## Install or upgrade

```console
curl --proto '=https' --tlsv1.2 -sSf \
  https://raw.githubusercontent.com/Rusk-programing-language/Rusk/main/toastset | sh
```

Prebuilt archives are attached for AArch64 and x86-64, glibc and musl, plus a
Windows x86-64 `rusk.exe`. Existing installs upgrade in place when `toastset`
is run again.

## Honest limits

- Linux remains the supported output platform. Windows x86-64 output is
  experimental and console-only: it does not parse arguments beyond `argv[0]`,
  has no environment, and file I/O, directories, process launch, sockets, and
  raw terminal mode are not implemented. The image is fixed-base with no base
  relocations.
- A toast is a whole-program container, not a linker. It cannot be combined,
  patched, or signed, and its FNV-1a checksum is an integrity check rather than
  a signature.
- The compiler still needs a Linux host to run Linux output. A Windows host can
  build and check, and can build the experimental `.exe`.
